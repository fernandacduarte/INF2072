## 1. Platform Purpose

A custom Pacman multi-agent RL environment for PUC-Rio graduate researchers. It provides a coordinated ghost-agent simulation where IQL, VDN, and QMIX algorithms can be trained and benchmarked under reproducible conditions, enabling comparison of coordination behaviors across algorithms and seeds.

### Design Philosophy

Reproducibility first. Every experiment must be traceable to an exact configuration (algorithm, seed, hyperparameters). Minimal dependencies — no web servers, no databases, no authentication. Research clarity over engineering polish: scripts are the primary interface.

## 2. Entity Hierarchy

```
Experiment Run
└── Algorithm Config (IQL / VDN / QMIX)
    └── Episode
        └── Reward Log (per-step rewards, coordination metrics)
```

<!-- REQ-ENT-001 -->
### Experiment Run

- What it represents: A single training or benchmark execution identified by algorithm, seed, and timestamp
- Visibility: local filesystem only; owned by the researcher who launched it
- Ownership: created by `run_pacman_benchmarl.py` or `run_benchmark.py`; no soft delete (outputs are files)
- Output location: `benchmarl_setup/runs/<timestamp>_<algorithm>_<seed>/`

### Algorithm Config

- What it represents: Hyperparameter configuration for one RL algorithm (IQL, VDN, or QMIX) as defined by BenchMARL
- Visibility: stored as YAML/JSON alongside each run
- Ownership: generated at run start; immutable after generation

### Episode

- What it represents: A single Pacman episode within a training run (one game from start to terminal state)
- Key domain rules: ghosts are cooperative agents sharing a joint reward signal; Pacman is the adversary controlled by a fixed policy or random agent

### Reward Log

- What it represents: The per-step and per-episode reward data emitted during training
- Format: CSV (for benchmark CSVs) and in-memory tensors during training
- Export: `benchmarl_setup/runs/` as CSV; plots generated by `plot_rewards.py`

## 3. Domain-Specific Concepts

**Ghost Coordination**: In the custom environment, ghosts are cooperative agents. Unlike standard Pacman where ghosts act independently, here they share a joint reward (e.g., +1 for catching Pacman, -0.1 per step). The multi-agent algorithms (VDN, QMIX) learn to coordinate ghost movements; IQL serves as the independent baseline.

**Multi-Seed Benchmark**: A benchmark run executes multiple independent training runs with different random seeds (default: 5 seeds) and aggregates results into a CSV with mean ± std statistics. This is the primary comparison artifact.

**BenchMARL Task Wrapper**: `benchmarl_setup/` contains adapter code that wraps the custom PettingZoo environment into the BenchMARL task interface. This adapter is the seam between domain logic and the RL framework.

## 8. User Experience Patterns (Domain-Driven)

<!-- REQ-UX-001 -->

**CLI-first interaction**: All user interactions occur via command-line arguments. No interactive prompts during training. Configuration is explicit at invocation time.

**Fail fast**: If a configuration error is detected (invalid algorithm name, missing dependency), the script exits immediately with a clear error message before starting expensive training.

**Progress visibility**: Training loops emit per-episode reward summaries to stdout so the researcher can monitor progress without reading log files.

## 13. Solution Representations

### US-001: Train a single algorithm

- **Story:** As a researcher, I want to train one algorithm on the custom Pacman environment so that I can observe its learning curve and save a checkpoint for evaluation.
- **Acceptance Criteria:**
  - Script accepts `--algorithm` and `--seed` args
  - Outputs reward CSV and checkpoint to `benchmarl_setup/runs/`

- **Story:** As a researcher, I want to benchmark multiple algorithms across multiple seeds so that I can produce statistically valid comparison results.
- **Acceptance Criteria:**
  - Script accepts `--algorithms` (comma-separated) and `--seeds` (comma-separated)
  - Outputs aggregated CSV with mean ± std per algorithm
  - Generates reward comparison plot

- **Story:** As a researcher, I want to evaluate a saved checkpoint in the Pacman environment so that I can visualize ghost coordination behavior.
- **Acceptance Criteria:**
  - Script accepts `--learner` and optional `--checkpoint` args
  - Renders or logs episode outcomes

## Decisions

> Validated design decisions in DRR shape. Append-only.

<!-- STATUS: proposed -->
### D-001: Use BenchMARL as the RL framework

**Context**: Choice of RL framework for implementing IQL, VDN, and QMIX. Alternatives: RLlib, EPyMARL, custom implementations.

**Decision**: Use BenchMARL (built on TorchRL) because it provides out-of-the-box implementations of IQL, VDN, and QMIX with a unified task interface, enabling fair algorithm comparison with minimal adapter code.

**Consequences**: Easier algorithm comparison (same hyperparameter conventions); constraint to BenchMARL's task API for the environment adapter; TorchRL dependency for replay buffers and collectors.

---

<!-- STATUS: proposed -->
### D-002: PettingZoo as the environment interface

**Context**: Choice of multi-agent environment interface. Alternatives: raw gym, RLlib multi-agent env.

**Decision**: Use PettingZoo's AEC (Agent Environment Cycle) API because BenchMARL supports it natively and it is the de-facto standard for multi-agent environments in Python.

**Consequences**: Custom Pacman environment must implement the PettingZoo AEC interface; enables reuse with other MARL frameworks.

---

### D-003: Adopt the Papoudakis-2021 benchmarking-reporting standard

**Context**: research-000037 reviewed Papoudakis et al. (2021, EPyMARL) for benchmarking best practices. The current aggregate (summarize_benchmark_runs.py) reports mean-over-runs only — discarding the variance from the 5 seeds the project already pays to run — and reads capture% from training-collection rollouts rather than a fixed greedy eval.

**Decision**: Standardise benchmark reporting on: (a) mean ± 95% CI across ≥5 seeds (constitution Q3), with rliable-style robust estimators (IQM + bootstrap CI, Agarwal 2021) given the small-n budget; (b) two-sided t-test (p<0.05) marking algorithms not significantly different from the best; (c) both max-return and all-evals average-return; (d) a fixed greedy N-episode evaluation decoupled from training collection.

**Consequences**: Defensible, citeable comparisons for the course report; modest added code in the summarizer and eval; wide CIs at n=5 surfaced honestly.

**Rejected Alternatives**: Raising seeds to 30–50 (ChatGPT suggestion) — rejected as infeasible at MARL compute cost and not RL-community practice; robust interval estimation is the accepted substitute. Reporting bare mean — rejected as it hides seed variance and enables over-claiming.
