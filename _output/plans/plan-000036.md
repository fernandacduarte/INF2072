## Agent interpretation

**Problem.** Against `hard` Pacman the ghosts never visibly pursue. research-000035 traced this to two
compounding causes: (a) the `+100` capture terminal almost never fires (structural capture difficulty),
and (b) the active `capture_v0_pure_potential_shaping` reward uses exact-telescoping PBRS that nets to
~zero against an evader who holds distance constant — so pursuit earns nothing cumulatively and the
policy converges to passivity. This plan delivers three phased, gated levers to (1) *measure* whether
capture is even attainable and whether the ghosts already follow, (2) *reward pursuit persistently*, and
(3) *make capture attainable* so it can anchor the learned behavior.

**Approach.** A single phased plan; Phase 1 is a gate whose result decides how much of Phases 2–3 to
run. All changes are additive and flag-gated so benchmark comparability is preserved:
- **Phase 1 (L1, diagnostic):** build a scripted greedy-pursuit ghost policy (the upper-bound pursuer)
  and a thin ceiling-evaluator CLI that drives the raw PettingZoo env (no BenchMARL) vs the configured
  Pacman, plus extend eval pursuit metrics (time-to-first-contact, % steps visible) reusing the existing
  `pursuit_fraction` / `_team_mean_distance` machinery in `eval_report.py`. Decides confound vs genuine
  limit before any retraining.
- **Phase 2 (L2, reward):** a new `CaptureV0ClosingReward` (`strategy_id=capture_v0_closing`) — sparse
  terminals + timestep + a **non-telescoping** per-step closing term (clipped reward for *reducing* team
  min-BFS distance) + the existing legal-moves-reduced containment term. New class only; existing
  strategies untouched.
- **Phase 3 (L3, mechanics):** a `capture_radius` constructor flag on `PacManEnvironment` (default `0` =
  today's co-location capture, fully back-compatible); `_is_capture_state` registers capture when a
  ghost is within `capture_radius` of Pacman after moves resolve. Threaded through one CLI flag.

**Alternatives rejected.**
- *Implement plan-000029's full evasiveness sweep for the ceiling*: that plan builds a whole dose-response
  pipeline across many `p` points — far more than the single hard-Pacman ceiling question here. This plan
  builds a minimal, self-contained ceiling evaluator; plan-000029 remains the fuller protocol and can
  reuse the scripted policy added in Phase 1.
- *Mutate `CaptureV0PurePotentialShaping` to be non-telescoping*: would silently invalidate the
  research-000031 A/B and every capture rate gathered under the PBRS arm. A new `strategy_id` keeps
  arms comparable (constitution Q1/auditability).
- *Switch PBRS to γ-matched `F = γΦ(s') − Φ(s)`*: that restores policy-invariance but a γ<1 term with
  Φ≤0 pays for *being far*, not for closing — the wrong incentive here. A direct (non-potential) closing
  reward is what makes pursuit emerge; we deliberately trade invariance for a pursuit bias (documented).
- *Make adjacency capture the default*: would change the task identity and break comparability with all
  prior runs. Flag-gated, default-off preserves the existing benchmark.
- *Ghost speed advantage*: largest change to environment identity; deferred to a future plan if Phase 1
  shows even scripted adjacency-pursuit cannot capture hard Pacman.

## Best practices

- **Additive, flag-gated changes** — new `strategy_id`, default-off `capture_radius`; never mutate existing
  reward classes or the default capture rule, so prior benchmark numbers stay comparable (constitution Q1).
- **Reproducibility-first** — ceiling evaluator takes explicit `--seeds`, seeds `_pacman_rng` per episode,
  records the git commit in its output (T4/C1); writes under `benchmarl_setup/runs/` (T2).
- **Reuse the canonical BFS / distance** — closing reward and ceiling metrics reuse the same BFS the PBRS
  potential uses (`CaptureV0PurePotentialShaping._mean_distance` / `eval_report._team_mean_distance`) so
  "distance" means the same thing everywhere.
- **Clip the closing term** — bound the per-step closing reward so a ghost cannot farm it by oscillating at
  the boundary of the safe-distance cordon (RC4 orbit hazard, research-000022).
- **Fail-fast CLI** — validate `--capture-radius >= 0`, non-empty seeds, valid reward id before running.
- **Never mix pre/post-rule capture rates** — any figure using `capture_radius>0` is labeled distinctly.

## Design decisions

- **User-visible impact**: A researcher gains (1) a `ceiling_eval.py` command answering "can *any* pursuer
  catch hard Pacman here?" without training, (2) richer eval output (time-to-first-contact, visible
  fraction) that shows pursuit quality even when capture rate is ~0, (3) a new `--reward-id
  capture_v0_closing` that visibly drives the ghosts to chase, and (4) an optional `--capture-radius 1`
  that makes capture attainable. Defaults are unchanged, so existing commands behave exactly as before.
- **Trade-offs accepted**: The closing reward gives up PBRS's policy-invariance guarantee in exchange for a
  persistent pursuit bias (the whole point — invariance preserves the very passivity we are fixing).
  Adjacency capture, when enabled, changes the task definition and requires re-baselining; we accept this
  behind an explicit flag rather than silently. The minimal ceiling evaluator duplicates a little logic
  that plan-000029 would generalize, accepted to keep this plan self-contained and shippable now.
- **Metacommunication impact**: New CLI help text tells the researcher that `capture_v0_closing` rewards
  *closing distance* (pursuit) rather than only capture, that `--capture-radius` changes the capture rule
  and must be re-baselined, and that `ceiling_eval.py` reports an *upper bound* achievable by scripted
  pursuit — so a low learned capture rate against a low ceiling is a structural result, not a training bug.
