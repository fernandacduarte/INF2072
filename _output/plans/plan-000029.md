## Agent interpretation

**Problem.** research-000028 designed a dose–response protocol to locate the Pacman-evasiveness threshold at which cooperative ghosts stop learning to capture. The benchmark harness already has the knobs (`--pacman-random-action-prob`, `eval_report` train-at-`e`/eval-at-`e`) but cannot (a) sweep `p` without folder collisions, (b) reproduce the stochastic Pacman across reruns, (c) normalize capture against an in-principle ceiling, or (d) render the dose–response figure. This plan adds the missing tooling and the one-line reproducibility fix.

**Approach.** Five tightly-coupled additions, all in the existing `benchmarl_setup/` (orchestration) and `custom_environment/` (domain) layers, plus one behavior-preserving edit:
1. Seed-pin `_pacman_rng` from the training seed inside `reset()` (mirrors the existing `_spawn_rng` seeding) — closes the T4 reproducibility hole for every `p>0` point including the `p=1.0` control.
2. A scripted **greedy-pursuit ghost policy** (BFS, the mirror image of `PacmanPolicy`) — drives an *upper-bound* ghost team that needs no training.
3. A **ceiling evaluator** that runs the raw PettingZoo env with the scripted ghosts against the configured Pacman, yielding `ceiling(p)` = capture rate achievable by near-optimal pursuit at evasiveness `p`.
4. A **sweep wrapper** that invokes `run_benchmark.py` once per `p` into `runs_sweep/p_<p>/`, holds `--pacman-difficulty hard` and `--randomize-spawns` constant, runs the ceiling per `p`, and writes an auditable `sweep_manifest.csv` (incl. git commit, R5/C1). Phases `pilot|interior|harden` and `--extended-frames` implement R3/R7.
5. An **aggregator/plotter** that joins the manifest + per-point `reward_eval` CSVs into the dose–response table and renders raw + normalized figures with per-seed scatter, bootstrap CI bands, ceiling line, annotated controls, and an optional per-algorithm logistic fit (R6/R8).

Why driving the raw env directly for the ceiling (not BenchMARL): the scripted ghosts are a fixed heuristic, so the whole MARL stack (models, collectors, checkpoints) is unnecessary overhead; `step(actions)` + `_is_capture_state()` are public and sufficient, and reusing the same env guarantees the ceiling and the learned-policy capture rate are measured under identical dynamics.

**Alternatives rejected.**
- *Encode `p` into `run_benchmark.py`'s output path* instead of a wrapper: changes a shared harness path convention used by other analyses; a wrapper with distinct `--save-folder` is non-invasive and reversible.
- *Cross-evaluate (train at `e1`, eval at `e2`) for the ceiling*: `eval_report.py` deliberately keeps checkpoint-defined difficulty; fighting that is fragile. A separate scripted evaluator is cleaner and answers the "is it even catchable" question directly.
- *Hungarian/minimax optimal pursuit for the ceiling*: true game-theoretic optimum is expensive and overkill; a greedy multi-source BFS pursuit with anti-clumping is a defensible, cheap upper-bound proxy. Documented as a proxy, not a proof.
- *Fold the ceiling into `eval_report.py`*: would entangle scripted and learned evaluation paths; kept separate for clarity and testability.

## Best practices

- **Reproducibility-first** (constitution): every random source seeded from the run seed; manifest records the git commit (C1).
- **Confound control**: only `p` varies; `--pacman-difficulty hard` (safe_distance=5) and `--randomize-spawns` held constant across all points so ghosts must pursue reactively rather than memorize a fixed route.
- **Fail-fast CLI** (design-standards): validate `p∈[0,1]`, non-empty seeds/algorithms, and existing folders before launching expensive runs.
- **Timestamped / keyed outputs** (T2): each `p` writes to `runs_sweep/p_<p>/`; no silent overwrite.
- **Matplotlib house style** (design-standards): 300 DPI PNG, one consistent color per algorithm, colorblind-safe palette, minimal gridlines.
- **Subprocess reuse**: the wrapper shells out to the existing `run_benchmark.py` rather than reimplementing training, keeping one training code path.

## Design decisions

- **User-visible impact.** The researcher gains three new commands: `run_evasiveness_sweep.py` (run the whole dose–response matrix in phases), `ceiling_eval.py` (measure the in-principle catchability at a given evasiveness), and `plot_evasiveness_sweep.py` (produce the presentation figures). Existing training/eval commands are unchanged. The only behavioral change to existing runs is that a stochastic Pacman is now exactly reproducible for a given seed.
- **Trade-offs accepted.** Gained: reproducible interior points, an interpretable normalized metric, auditable provenance, and presentation-ready figures. Given up: the scripted ceiling is a greedy proxy for optimal pursuit (documented), and the seed-pin makes per-seed Pacman deterministic — intended, but it means stochastic diversity now comes only from varying the seed (already the design).
- **Metacommunication impact.** The sweep wrapper prints, per point, "evasiveness e = 1 − p", the save-folder, and the ceiling capture rate, so I tell you exactly which condition is running and how catchable it is in principle — you read progress without opening files. The plotter annotates the two endpoints as "positive control (random Pacman)" and "negative control (perfect evader)", communicating the experimental rigor directly on the figure.

### Step 2 — Scripted greedy-pursuit ghost policy
- [ ] Add a BFS-based ghost policy that drives a near-optimal pursuit team (the catchability ceiling).
- **Files:** `custom_environment/env/domain/ghost_pursuit_policy.py`
- **References:** mirror `custom_environment/env/domain/pacman_policy.py` (multi-source BFS, `_legal_actions`, `_MOVES`, `Action`/`Observation` from `constant.py`); env exposes `ghosts[*].current_position`, `pacman.current_position`, `global_view`.
- **Interface:** `class GhostPursuitPolicy` with `choose_actions(global_view, ghost_positions, pacman_pos) -> list[Action]`. Each ghost picks the legal move minimizing BFS distance to Pacman; apply anti-clumping so two ghosts don't collapse onto the same corridor (e.g., after assigning ghost 1's target move, penalize cells within distance ≤1 of an already-chosen ghost's destination, breaking ties by spreading). **Deadlock fallback:** when anti-clumping leaves a ghost with no improving non-clumping legal move (e.g., a narrow corridor where the only forward cell is taken), return the best available legal move (or stay) — never raise or loop. Stateless; accepts optional `rng` for deterministic tie-breaking.
- **Interface (produced):** `GhostPursuitPolicy.choose_actions(...)` consumed by Step 3.
- **Verify:** on a small open grid with a ghost adjacent to Pacman, the chosen move strictly reduces that ghost's BFS distance; two ghosts on the same row do not pick identical destination cells; on a one-wide corridor where both ghosts contend for the only forward cell, the call returns a legal action for each without raising.
- **Tests:** (a) when a ghost is two cells from Pacman down an open corridor, `choose_actions` returns the move toward Pacman (distance decreases by 1); (b) when two ghosts would step onto the same cell, the policy returns distinct destinations; (c) on a narrow corridor with no non-clumping improving move, the policy returns a legal fallback action for every ghost without raising or looping.
