## Agent interpretation

**Problem**: IQL training is already wired (`run_pacman_benchmarl.py --algorithm iql`), and "winning" means the cooperative ghost team captures the deterministic, defense-first Pacman before timeout. But there is no way to *measure* whether a trained IQL policy wins (only reward proxies exist), and the shipped defaults (`--max-frames 5000`, BenchMARL stock IQL hyperparameters) are smoke-test-scale and do not converge to a reliably winning policy — especially after Pacman was made defense-first (commit c7fbc11). So "implement IQL learning to win" decomposes into: (1) a reproducible **win-rate evaluation harness** that quantifies captures over N episodes from a checkpoint, and (2) **tuning + reward shaping** so IQL demonstrably reaches a target win rate.

**Approach**: Two confirmed deliverables (per scoping with the user):
1. *Win-rate harness* — add a headless, multi-episode evaluation path to `custom_environment/eval.py` that loads a checkpoint, runs N episodes, counts ghost captures vs Pacman wins vs timeouts, and reports a win-rate summary (optionally to CSV). Because the environment is fully deterministic (deterministic Pacman policy + fixed map-authored spawns + greedy ghost policy), every greedy episode is identical and a naive "win rate" would be a trivial 0% or 100%. The harness therefore evaluates with **seeded stochastic ghost-action sampling** (an `--eval-epsilon`, default `0.05`, with per-episode torch seeding) so episodes vary and the metric reflects policy robustness near-greedy. `--eval-epsilon 0` collapses to the deterministic single outcome.
2. *Tuned IQL + reward shaping* — raise the training budget default, override stock IQL/exploration hyperparameters for convergence, and conservatively retune reward constants to strengthen the pursuit→capture gradient. Pacman policy and the 5×5 observation model stay frozen (confirmed). Reward-constant changes are shared across all algorithms (constants are global), which keeps the IQL/VDN/QMIX comparison fair.

**Alternatives rejected**:
- *Vary the environment seed per episode instead of policy exploration* — rejected: the env transition is deterministic, so seed variation alone produces identical episodes; it would not yield a meaningful win-rate distribution without touching spawns (out of the frozen-env scope).
- *Make reward weights CLI-configurable* — rejected for now: adds surface area; the project convention is global reward constants in `constant.py`, and a single retuned, documented set keeps runs reproducible and comparable.
- *Lower Pacman difficulty (curriculum)* — rejected: user froze the Pacman policy; tuning + shaping must carry the win.

## Best practices

- Reuse the existing checkpoint-resolution helpers (`_best_checkpoint_for_learner`, `_latest_checkpoint_for_learner`, `_unwrap_pacman_env`) rather than duplicating load logic.
- Keep the win/loss classification consistent with `_build_final_result` (capture → ghosts win; timeout/agents-cleared → Pacman wins) so the harness and the renderer agree.
- A pure aggregation helper (`summarize_win_rate`) separated from the rollout loop so it is unit-testable without a trained checkpoint (satisfies constitution Q2/Q1 — measurable, tested).
- Hyperparameter overrides applied after `get_from_yaml()` so BenchMARL's config schema stays the source of truth.
- Reward-constant edits change magnitudes only (not signs/structure), preserving existing smoke-test invariants in `test/test_pallet_win.py`.

## Design decisions

- **User-visible impact**: The researcher gains `py -3.11 custom_environment\eval.py --learner iql --episodes 50`, which prints a win-rate summary (`ghosts win X% | pacman win Y% | timeout Z%`) and can write a CSV — a concrete, citable "does IQL win?" answer. Default training now runs at a convergence-scale budget instead of the 5000-frame smoke value, and ghosts pursue Pacman more decisively due to the sharpened reward gradient.
- **Trade-offs accepted**: Gained a measurable win criterion and a converging recipe; gave up the (misleadingly cheap) 5000-frame default runtime — a default IQL run now takes meaningfully longer. Reward retuning shifts absolute reward magnitudes, so reward curves are not directly comparable to pre-change runs (documented in README).
- **Metacommunication impact**: The tool now communicates *whether the ghosts actually win*, not just an opaque reward number. The eval summary line tells the researcher, in their own terms ("Ghosts win 72% of 50 episodes"), that coordination is working — directly serving US-003 and the JM-TB-001 "verify ghost coordination is actually occurring" intent.
